DPR STEP-BY-STEP — TEAM DRAFT PROFILE
=================================
Run one command at a time. Preparation -> source DROID -> conversion ->
veraPDF -> QA -> metadata -> BagIt -> independent ingest -> OCFL.

READ FIRST
----------
TEAM_REVIEW_IMPLEMENTATION.md describes the new identity scheme and remaining
profile decisions. preservation_config.json is a clearly labelled synthetic
TEST registry. Replace it with the approved operator/tool registry for production.
Use --strict-profile at PoC6 and PoC9 to reject draft configuration/gaps.
Existing packages are never replaced. Existing bare-UUID OCFL objects require
an explicit migration/re-ingest decision; the code does not edit their inventory IDs.

POWERSHELL VARIABLES (edit paths to installed tools)
--------------------------------------------------
$dprRoot = (Get-Location).Path
$dprPython = 'C:\ProgramData\anaconda3\python.exe'
$dprJob = '2026_012405'
$dprDmsJob = '12405.26'
$dprBatchStaging = Join-Path $dprRoot 'staging\batch_001'
$dprAip = Join-Path $dprRoot 'AIP'
$dprRecords = Join-Path $dprRoot 'ingest-records'
$dprRegistry = Join-Path $dprRoot 'preservation_config.json'
$dprJava = 'FULL_PATH_TO_java.exe'
$dprDroid = 'FULL_PATH_TO_droid-command-line.jar'
$dprLicence = 'FULL_PATH_TO_ASPOSE.lic'
$dprVera = 'FULL_PATH_TO_verapdf.bat'

1. DISCOVER / RECEIVE / PREPARE
-----------------------------
& $dprPython specific_step1.py --root $dprRoot --job-id $dprJob

2. SOURCE CHARACTERIZATION
--------------------------
& $dprPython poc5_droid.py --preparation-dir preparation --job-id $dprJob --java $dprJava --droid-jar $dprDroid

3. CONVERT PDF/A
----------------
& $dprPython poc2_aspose.py --preparation-dir preparation --job-id $dprJob --converter-project DprPdfaConverter\DprPdfaConverter.csproj --license $dprLicence

4. VALIDATE CONFORMANCE
----------------------
& $dprPython poc3_verapdf.py --preparation-dir preparation --job-id $dprJob --verapdf $dprVera

5. FIDELITY QA
--------------
& $dprPython poc4_qa.py --preparation-dir preparation --job-id $dprJob

6. TEAM DRAFT METADATA / POST-CONVERSION CHARACTERIZATION
---------------------------------------------------------
& $dprPython poc6_metadata.py --profile --preparation-dir preparation --dms-job-id $dprDmsJob --server 'Pekan.ext.wto, 14133' --database DOL2DB --driver 'ODBC Driver 17 for SQL Server' --xsd schemas\dol-metadata-v-03.xsd --aip-root $dprAip --agent-registry $dprRegistry --java $dprJava --droid-jar $dprDroid

For an offline synthetic test, omit --java/--droid-jar: missing PUIDs are reported
as draft gaps; no format claims are invented. For production, add --strict-profile.

7. BUILD DISTINCT SIP
--------------------
& $dprPython poc7_bagit.py --preparation-dir preparation --staging-dir $dprBatchStaging --job-id $dprJob --aip-root $dprAip --agent-registry $dprRegistry

For subsequent changed packages use a NEW batch staging root. The proposed
selection basis can be overridden with --selection-basis language_added (or
modified_files, metadata_change, rendition_added, etc.) and --description.
For a supplied batch UUID, use PoC6 --batch-id and PoC7 --bag-group-id consistently.

8. VERIFY EXACT SIP / PREDECESSOR
--------------------------------
& $dprPython poc8_ingest_worker.py --staging-dir $dprBatchStaging --job-id $dprJob --aip-root $dprAip --ingest-records-dir $dprRecords

9. APPEND AIP / REQUIRE INDEPENDENT OCFL VALIDATION
--------------------------------------------------
& $dprPython poc9_ocfl_ingest.py --staging-dir $dprBatchStaging --job-id $dprJob --aip-root $dprAip --ingest-records-dir $dprRecords --agent-registry $dprRegistry --ocfl-validator validate_ocfl.py --validator-python $dprPython --require-independent-validator

Add --strict-profile for production. Commit identity comes from the configured
operator; --user-name/--user-address, if supplied, must match that registry.
A failed check holds the SIP and commits no new version. The received bag remains
unchanged; ingest PREMIS/METS are produced in a separate workspace.

10. MONITOR
-----------
& $dprPython poc_monitor.py --preparation-dir preparation --staging-dir staging --ingest-records-dir $dprRecords --aip-root $dprAip --excel DPR_Master.xlsx

TESTS / READ-ONLY VALIDATION
---------------------------
& $dprPython -m unittest discover -s tests -v
& $dprPython validate_ocfl.py FULL_PATH_TO_SYNTHETIC_OCFL_OBJECT

The validator's Python needs bagit/fsspec/s3fs/python-dateutil. Pairtree and the
OCFL validator source are pinned under vendor/. This workstation's base Anaconda
has the needed runtime dependencies. No digest-skip options are used.

LEGACY COMPATIBILITY
--------------------
PoC6 without --profile uses the earlier local -poc.xsd metadata path. To ingest
an existing legacy-scheme test bag, both PoC8 and PoC9 require the explicit
--allow-legacy-package switch. This does not retrofit profile conformance or
rewrite existing versions. Do not use that switch to bypass failed profile gates.

SIGNED NOTIFICATION PDFs
------------------------
The user authorized retaining signed originals and creating separate unsigned
PDF/A derivatives during the live 12405.26 example. To enable this explicitly,
add --allow-signed-derivative to PoC2 and build the updated converter source.
The flag is off by default. No signed original is rewritten. The signature
policy is recorded in conversion JSON and PREMIS; veraPDF and QA still gate it.
The live example is under runs/rb94079/FINAL_RESULT.html.

The sealed received SIP and BagIt manifests remain unchanged. Supply --agent-registry at Step 8 with the same registry used for Step 9. Step 9 requires the hash-verified Step 8 snapshot; rerun Step 8 for older pending bags. Existing committed AIPs need no reprocessing.
OCFL INVENTORIES
Historical version inventories retain their historical heads and cumulative histories. Root inventory.json MUST equal the latest version inventory.json; older inventories remain unchanged.

It is covered by OCFL SHA-512 fixity and AIP METS. Older summaries are retained unchanged. Checksums are read from inventory.json to avoid self-referential checksums. Required inventory.json files remain cumulative. Existing committed AIPs are not rewritten.

EXPLICIT RECONVERSION
Add --reconvert-source-id SOURCE_UUID --reconversion-token LOWERCASE_UUID4 to the normal poc2_aspose.py command.
Reuse the same token to resume the same request. Old master/report files remain unchanged.
Then run PoC3, PoC4, PoC6 --profile, PoC7, PoC8 and PoC9 normally.
A repository update is routed to master_reconversion. A label alone does not request reconversion.

HUMAN QA DECISION
python adjudicate_qa.py --object-dir PREPARATION/JOB_ID --decision decision.json --agent-registry registry.json
decision.json fields: reviewer_uuid, master_file_id, source_sha512, master_sha512, qa_report_sha512, reviewed_at (timezone-qualified), verdict (accept/reject), reason.
reviewer_uuid must identify registry.operator or a person in registry.reviewers.
The active master must still have a passing veraPDF record. All evidence hashes are checked.
The supplied decision is retained and linked in PREMIS, with the reviewer as implementer.
No automated report is rewritten and no review result is fabricated.
